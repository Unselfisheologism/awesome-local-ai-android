# Contributing to Awesome Local AI Android

Thanks for helping keep this list focused and useful.

## What To Add

Add items that are clearly relevant to Android local AI, Termux, or mobile coding workflows.

Good additions include:

- Android apps for local model use.
- Runtime and inference projects with Android support.
- Termux add-ons, scripts, and workflow tools.
- Practical documentation or curated resource lists.

## What We Accept

- Official upstream repo or official documentation links.
- A short description that says what the project does.
- A clear category placement.
- A note if the project is archived, experimental, or channel-specific.

## What We Do Not Want

- Generic AI tools with no Android or Termux angle.
- Mirrors, reposts, link farms, or affiliate pages.
- Duplicate entries with different names.
- Vague descriptions like "awesome tool" or "best app ever".

## Entry Format

Use a single bullet in this shape:

```md
- [Project Name](https://example.com) - One-sentence description.
```

If a project is archived or has a caveat, put that in the description:

```md
- [Example Project](https://example.com) - Archived but still useful reference for ...
```

## Placement Rules

- Keep entries in the most relevant section.
- Prefer stable upstream naming over nicknames.
- If a project spans multiple sections, place it where it is most useful to readers.

## Before Opening A Pull Request

- Check that the link still resolves.
- Keep the change small and focused.
- Avoid touching unrelated files.
- Add only one entry per PR when possible.
- Mention why the entry belongs here if the fit is not obvious.

## Review Expectations

PRs are easier to review when they include:

- the exact new entry or edit
- a short reason for inclusion
- any maintenance caveat, such as archived status or Android channel notes
